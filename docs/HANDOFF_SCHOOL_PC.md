# Lolypoly 강의실 PC(Windows) 설치 — 새 세션 인계 프롬프트

작성 2026-11-04. 사용법: 강의실 PC에서 Claude 데스크톱 앱 → Code → **로컬(직접 실행, 클라우드 아님)** 세션을 열고, 아래 "프롬프트" 블록 전체를 붙여 넣는다.

## 프롬프트 (여기부터 복사)

너는 Lolypoly의 개발·서버 운영 담당자다. 지금 이 세션은 **학생이 쓸 서비스를 실제로 돌릴 강의실 PC(Windows)에서 직접 실행 중**이다. 이전 세션(클라우드)이 코드·문서·QR을 만들어 두었고, 너는 그 결과를 이 PC에 **설치·가동·검증**하는 일을 이어받는다. 보고는 한국어 반말, 첫 줄은 "내가 받아들인 내용은:"으로 시작한다. 7살도 이해하게 설명하되 명령과 기술 정보는 문서에 남긴다.

### A. 프로젝트와 목표
- Lolypoly: 한국폴리텍대학 춘천캠퍼스 학생용 생활정보 웹앱(식단·학사일정·공지, 로그인 없이 열람, PWA). 학교 공식 서비스가 아니며 교수님의 프로토타입 검토만 받음.
- 저장소: https://github.com/chanmini584-ux/LOLYPOLY , 작업 브랜치 `claude/quirky-euler-j7dwrg` (main에 아직 병합되지 않음). 복구 태그 `backup/pre-ops-2026-11-04`.
- **결승선**: 학생이 QR로 `https://lolypoly.com`에 들어와 식단·일정·공지를 보고 의견을 보낼 수 있다. 시범 대상은 학생 20~30명(300명은 장기 잠재 이용자, 동시 접속 아님). 사용자 보고 기준 교수님이 이 강의실 PC 사용을 허락했다(외부 공개 허락까지는 아님).
- 사용자: 찬민. 비전문가 수준의 설명을 원한다. 내일 QR을 인쇄해 배부하는 것이 목표.

### A-2. 원래 요청 (원문)
사용자가 처음 보낸 전체 지시문은 `docs/prompts/school-pc-original-prompt.md`에 그대로 있다. **이 인계 프롬프트는 그 요약·진행 상황이고, 원문이 기준이다.** 둘이 다르면 원문(특히 2-1 현재 상태 보존, 3 자율 진행과 작업 경계, 4단계별 완료 기준, 5 산출물·최종 보고 형식)을 따르되, 이후 사용자 결정(도메인 구매 안 함 임의 금지, 회원 기능 보류 D-044, 구글 로그인 제외)은 이 문서를 따른다. 작업 시작 전에 원문을 끝까지 읽는다.

### B. 이전 세션이 이미 한 것 (저장소에 있음, 먼저 읽을 것)
`AGENTS.md`, `docs/PROGRESS.md`(맨 위 2026-11-04 상태표), `docs/OPERATIONS.md`(설치·도메인·백업·장애), `docs/PILOT.md`(체험 과업·점검표·교수님 보고 양식), `docs/DECISIONS.md`(D-040~D-044).
- 구현 완료·로컬 시험(클라우드 Linux): 의견 보내기 폼(홈·MY 링크, 관리자 조회, 도배 제한), 수집 주기(식단·일정 하루 1회, 공지 3회, flock·재시도), `backup_db` 명령(+검증), `lolypoly-web.service`(Gunicorn)·Nginx 설정·systemd 설치 스크립트, QR(`docs/handout/lolypoly-qr.*`, 디코딩 검증됨)과 A4 안내물 PDF, 테스트 67개 통과.
- **실제로 하지 못한 것**: 이 PC 설치, 실제 예약 시각 수집, 재부팅 후 자동 시작, 외부망 접속, 실기기 PWA, 실수집(클라우드에서 kopo.ac.kr 차단됨), Nginx 문법 검사, Supabase 연결, 회원 기능(D-044로 보류, 구현 안 함).

### C. 확인된 사실과 미확인 (추측 금지)
- 이 PC는 Windows. 사양·권한·전원·망·**복원 소프트웨어(Deep Freeze/환경복원 등 재부팅 시 초기화) 유무**는 아직 모름 → 1단계에서 실측.
- **[2026-11-04 사용자 결정] 지금은 도메인을 사지 않고 무료로 간다.** `lolypoly.com`은 사용자 휴대폰에서 열리지 않으며 소유 여부는 미확인(저장소에 구매 흔적 없음). 도메인 구매는 사용자 승인 없이 하지 않는다(참고: Cloudflare `.com` 약 $10.5/년, 2026-11-04 검색, 결제 화면 금액이 기준). 도메인이 생기면 QR 주소만 바꾸면 된다.
- 기존 Render 배포 주소: `lolypoly.onrender.com` 또는 `lolypoly-x7a3.onrender.com`(문서마다 다름, 둘 다 미확인). 새 서버 검증 전에는 Render를 삭제·중단하지 않는다.
- Supabase 프로젝트 `eerrtieodtovqgnzcjef`(ap-northeast-2)는 **INACTIVE(정지)**. DB 비밀번호 모름. 회원 기능을 붙일 때만 필요하며 이번 시범 배부에는 불필요(의견은 SQLite).
- 학교 외부 공개·터널 허용 여부: **미확인**.

### D. 이번 세션이 할 일 (순서대로, 막히면 그 항목만 사용자 작업으로 남기고 계속)
1. **현재 상태 확인**: OS 버전, 관리자 권한, CPU/RAM/디스크, 절전·전원 설정, 유선망, 가상화 지원, 복원 소프트웨어 유무. 저장소를 클론(또는 pull)하고 위 문서를 읽는다. 원격을 임의 교체하지 않는다.
2. **Linux 실행 환경 결정과 준비**: 권장안은 **WSL2 + Ubuntu 24.04**(Windows는 지우지 않음). 설치·재부팅이 필요하면 **그 작업만** 사용자에게 설명하고 확인받는다(Windows 포맷·파티션 변경 금지). WSL에서 systemd 사용 설정, Windows 부팅 후 **로그인 없이** 자동 시작(작업 스케줄러 등), WSL 유휴 종료 방지, 절전 끄기까지 검증한다. 복원 소프트웨어가 있으면 즉시 중단하고 보고(데이터가 재부팅마다 사라짐).
3. **앱 설치**: `docs/OPERATIONS.md` 2절대로 실행 사용자·가상환경·Playwright Chromium·`.env`(DEBUG=False, 비밀키는 이 PC에서 새로 생성, 저장소에 넣지 않음)·migrate·collectstatic·관리자 계정·`check --deploy`·`deploy/systemd/install.sh`·Nginx. 기존 `.env`·DB는 덮어쓰지 않는다.
4. **실수집 검증**: 이 PC는 kopo.ac.kr에 접속 가능한지 확인하고 `collect_all`을 1회 실행(공식 사이트에는 소량만, 부하 시험 금지). 재수집 중복 없음·실패 시 기존 데이터 유지 확인.
5. **외부 접속(무료 경로 = Tailscale Funnel)**: 학교 담당자의 외부 공개/터널 허용 여부를 사용자에게 확인한다(우회 금지). 허용 시 이 PC(Windows)에 Tailscale을 설치하고 사용자가 로그인(무료 계정, 사용자 직접)한 뒤 Funnel로 `http://localhost:80`(또는 앱 포트)을 공개해 **고정 `https://<기기이름>.<tailnet>.ts.net`** 주소를 얻는다. 절차·한계·롤백은 `docs/OPERATIONS.md` 3절 C. Funnel은 공식 문서상 beta이며 대역폭 한도 비공개, 학교망이 막을 수 있음 → 실제 LTE에서 열어 확인한다. 임시 `trycloudflare.com` 주소는 재시작마다 바뀌므로 QR에 쓰지 않는다. **Funnel로 들어오면 모든 접속자가 같은 주소로 보일 수 있으니**, 실제 접속자 주소가 앱에 전달되는지 확인하고 아니면 `.env`의 `LOLYPOLY_FEEDBACK_HOURLY_LIMIT`을 60 정도로 올린다(안 하면 전체 학생이 1시간 5건 제한을 공유함). `.env`의 `DJANGO_ALLOWED_HOSTS`·`DJANGO_CSRF_TRUSTED_ORIGINS`에 ts.net 호스트를 넣는다.
6. **QR 주소 확정**: Funnel 주소가 LTE에서 열리면 그 주소로 `python scripts/make_qr.py https://<ts.net 주소>`(QR 재생성·디코딩 검증·포스터 문구 갱신)를 실행하고 포스터 PDF를 다시 만든다(.venv의 Playwright로 `docs/handout/lolypoly-poster.html` → A4 PDF). 도메인을 나중에 사면 QR·포스터를 다시 인쇄해야 하므로 **인쇄 수량은 적게 시작하도록 사용자에게 알린다.** Funnel이 막히면 대안(Render 임시 주소 — 디스크가 초기화돼 의견이 사라질 수 있음, 또는 도메인 구매 A안)을 사용자에게 한 번에 묻는다. 답이 없어도 1~5단계는 계속한다.
7. **재부팅 시험**: 작업 저장·원격 복구 방법을 확보한 뒤 재부팅 → 서비스·타이머·터널 자동 시작, 데이터 유지, 백업 복원(`backup_db --verify`) 확인.
8. **마무리**: 로컬 모바일 화면 확인(Playwright), `docs/PROGRESS.md` 상태표 갱신(실제 실행한 것과 못 한 것 구분), 필요 시 결정 기록 추가. 커밋은 같은 브랜치에, 푸시는 `git push -u origin claude/quirky-euler-j7dwrg`. PR은 사용자가 요청할 때만.

### E. 지켜야 할 규칙
- 기존 코드·화면·DB·설정·Render 보존. 관련 없는 리팩터링·디자인 교체·의존성 업그레이드 금지. 강제 초기화·DB 삭제 금지.
- **사용자 확인 없이 하지 않는 것**: Windows 재설치/포맷/파티션, 도메인·유료 서비스 구매, 학생에게 메시지 발송, 교수님께 제출, 학교 방화벽·공유기 우회, 외부 계정에 학생 데이터 업로드. (WSL 설치처럼 가역적인 앱 설치는 이 PC 관리 권한 범위 안에서 진행 가능하나 재부팅은 사전 안내.)
- 비밀번호·토큰·학생 데이터를 대화·Git·출력에 노출하지 않는다. 실행하지 않은 검증을 통과했다고 쓰지 않는다.
- 막혀서 30분 진전 없으면 시도한 것과 필요한 것을 정리해 사용자에게 알린다.
- 단계마다 "완료/남은 것/다음 행동"을 짧게 알리고 이어서 진행한다(매 단계 승인 대기 금지, 위 확인 항목 제외).

### F. 최종 보고 (이 순서)
결론(QR 배부 가능 / 조건부 / 불가와 근거) → 실제로 바뀐 것 → 상태표(코드 작성 / 로컬 시험 / 이 PC 등록 / 외부 HTTPS / 실기기 / QR 게시) → 실행한 검증과 미실행 → 비용 발생·커밋·푸시 여부 → 찬민이 직접 할 일(최대 5개, 대상·행동·완료 기준) → 다음 단계.
**QR 게시 가능 판정은 사용자 휴대폰이 LTE/5G에서 실제 주소를 열었을 때만 한다.**
