# 버스 노선 안내 1차(정적) 설계

- 작성: 2026-11-05 · 상태: 사용자 시안 승인(2026-11-05), 구현 전
- 관련 결정: D-040(신규, 아래) · D-006(하단 탭 5개) · D-037(플래너 디자인)

## 1. 목표와 결승선

폴리텍입구 정류장을 지나는 버스 노선을 학생이 앱에서 한눈에 본다.

**결승선**: 홈 바로가기 "버스" → `/bus/` 화면에서 3개 노선(901·동산1·동산3)의 주요 정류장 줄그림과 기점·종점 출발 시각이 보이고, 폴리텍입구가 형광펜으로 표시된다.

범위 밖(2차): 실시간 도착 정보(TAGO API — 춘천 지원 여부 미확인, 사용자 키 발급 후 별도 설계), 다음 버스 계산, 지도.

## 2. 데이터 출처와 한계

- 출처: 「춘천시내버스 노선안내」 2026.09.30 (춘천시, 사용자가 올린 PDF 발췌 35쪽).
- 폴리텍입구가 나오는 곳(직접 확인):

| 노선 | PDF 쪽 | 구간 | 기점 출발 | 종점 출발 | 각주(원문) |
|---|---|---|---|---|---|
| 901 (대학병원노선) | 78~79 | 후평동종점 ↔ 굴지리종점 | 06:00, 11:35(군자리) | 07:30(군자리), 13:15(폴리텍입구) | 괄호 = 경유지 |
| 동산1 (마을버스) | 114~115 | 기종점: 석사삼익A(거두리부영A) | 15:25, 18:30 | 16:25, 19:40, 21:40 | 폴리텍 경유 편 표시 없음 |
| 동산3 (마을버스) | 118~119 | — | 14:20* | 15:40** | *조양4리 경유, **폴리텍 입구 경유 |

- **시각은 기점·종점 출발 시각이다. 폴리텍입구 도착 시각이 아니다.** 화면에서도 그렇게 표기한다.
- 동산1은 어느 편이 폴리텍입구를 들르는지 노선도에 없다 → 화면에 "모든 편이 들르는지는 노선도에 표시가 없어요" 문구.
- PDF가 전체(192쪽)의 일부라 다른 노선이 더 있을 수 있다(확인 불가).
- "폴리텍입구"가 캠퍼스 앞 정류장인지는 사용자 확인 필요.
- 마을버스 정류장은 PDF 지도에 이름이 있는 **주요 정류장만** 옮긴다(사용자 선택). 모든 노선 동일 규칙.

## 3. 결정 D-040 (DECISIONS.md에 추가)

버스 노선은 수집·DB 대신 `campus/bus_data.py`에 손으로 옮긴 고정 데이터로 둔다.
- 근거: 수집할 공식 웹 페이지가 없는 PDF 자료, 1년에 몇 번 바뀜, 마이그레이션 불필요, 2차 실시간은 API로 따로 하므로 지금 모델을 만들면 버리게 됨.
- 상태 표기: Mock 아님 — "실제 데이터(수동 입력)". 화면에 출처·기준일 표시.
- 재검토: 노선도 개정 시, 실시간 API 도입 시.

## 5. 화면 (승인된 시안)

- 제목 "버스"(손글씨), 안내 "폴리텍입구 정류장을 지나는 노선이에요."
- 노선 칩: 901 · 동산1 · 동산3 (`?route=`, JS 없음, 44px 이상).
- 줄그림: 기점·종점 ● + "기점/종점" 태그, 정류장 ○, 폴리텍입구 빨간 ◉ + 형광펜 + 굵게. 세로선은 민트 파스텔.
- 시각: "기점 출발 / 종점 출발" 행, 시각 칸. 폴리텍을 들르는 편은 빨간 테두리 칸 + "폴리텍입구" 문구.
- 각주 + "시각은 기점·종점 출발 시각이에요(정류장 도착 시각 아님)."
- 출처 상자(라벤더): "춘천시내버스 노선안내(2026.09.30) 기준 · 직접 옮겨 적은 정보예요. 운행은 바뀔 수 있어요."
- 하단 탭 5개 유지, 버스 화면에서는 현재 탭 표시 없음.
- 접근성: 줄그림은 `<ol>`이라 스크린리더가 순서대로 읽음. 폴리텍입구에 `visually-hidden` "(우리 학교 정류장)".

## 6. 오류·경계 상황

- 모르는 `route` 값 → 첫 노선(404 아님).
- 노선에 폴리텍입구가 없으면(데이터 실수) 형광펜 없이 그대로 표시 — 테스트로 막는다.
- 긴 정류장 이름은 줄바꿈 허용(`keep-all`), 375px에서 가로 넘침 없음.
- 오프라인: 기존 서비스 워커 규칙대로 방문한 화면은 저장됨(추가 작업 없음).
