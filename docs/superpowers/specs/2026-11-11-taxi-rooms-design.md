# 번개 택시방 (택시 합승 임시 채팅) 설계

- 작성: 2026-11-11 · 상태: 사용자 요구사항·시안·설계 승인(2026-11-11), 구현 전
- 대상 버전: 다음 기능 릴리스 **v0.4.0-beta** (구현 중에는 README `Unreleased`에 기록)
- 관련 결정(신규): D-070(채팅을 범위에 포함, 택시 합승 전용), D-071(실시간은 3초 폴링)
- 기존 기준: D-059(커뮤니티 범위), 익명 표시·신고·차단·운영 기록·`purge_community` 정리 방식

## 1. 목표와 결승선

같은 방향으로 가는 학생끼리 택시를 나눠 탈 사람을 빠르게 모으고, 짧게 대화한 뒤 흔적 없이 끝낸다.

**결승선**: 로그인한 학생이 커뮤니티 → "택시 같이 타기"에서 방(출발 시각·출발지·도착지·정원)을 만들고,
다른 학생이 선착순으로 들어와 익명으로 대화하며, 방장이 터뜨리거나 출발 1시간 뒤 방이 닫히면 학생 화면에서 사라지고
7일 뒤 서버에서도 지워진다.

범위 밖: 사진·위치 공유, 요금 정산, 푸시 알림, 1:1 대화, 택시 외 용도, 웹소켓.

## 2. 사용자 결정 (2026-11-11)

| 항목 | 결정 |
|---|---|
| 용도 | 택시 합승 전용 |
| 정원 | 방장이 2·3·4명 중 선택(방장 포함), 선착순 입장, 정원 차면 입장 불가 |
| 입장·퇴장 | 방이 열려 있는 동안 정원 안에서 자유롭게 |
| 닫힘 | 방장 '터뜨리기' 또는 출발 1시간 뒤 자동. 닫히면 학생 화면에서 즉시 사라짐 |
| 참여 범위 | 로그인한 학생 전체(학과 무관). 비로그인은 목록도 못 봄 |
| 익명 | 다른 학생에게는 '방장'·'익명N'. 운영자·서버는 계정 확인 가능 |
| 보관 | 닫힌 뒤 7일 자동 삭제. 처리 전 신고가 있으면 처리 끝날 때까지 보관 |
| 실시간 | 3초마다 새 메시지 확인(폴링) |

## 3. 설계에서 정한 것 (사용자 승인)

- 방 안 표시: 방장 = '방장', 참여자 = 방마다 1부터 새로 매기는 '익명N'. 나갔다 다시 들어오면 같은 번호.
- 메시지: 글자만, 최대 200자. 입장·퇴장·정원 마감·방 닫힘은 시스템 메시지.
- 제한: 방장인 열린 방 최대 1개, 참여 중(방장 포함) 열린 방 최대 2개. 출발 시각은 지금 ~ 24시간 안.
- 방장은 '나가기' 없이 '터뜨리기'만(관리자가 없는 방 방지).
- 내가 차단한 사람이 방장인 방은 목록에서 숨김. 방 안에서 차단한 사람의 메시지는 '차단한 사용자의 메시지'로 가림.
- 신고: 방(제목·장소·한마디)과 메시지 모두. 기존 운영자 화면·운영 기록에 함께 표시.
- 위치: 커뮤니티 홈 위쪽 카드 "택시 같이 타기" → `/community/taxi/`. 하단 탭은 그대로.

## 4. 데이터 (community 앱, 마이그레이션 = 표 추가 + Report·ModerationLog 칸 추가)

```
TaxiRoom      departs_at(출발, UTC 저장·서울 표시), origin(30자), destination(30자), capacity(2~4),
              note(40자, 선택), host → User, status(open/closed/hidden), created_at, closed_at,
              close_reason(host/expired/moderator)
TaxiMember    room → TaxiRoom, user → User, number(방장 0, 익명 1~3), joined_at, left_at(null=참여 중)
              유일: (room, user) — 다시 들어오면 같은 행·같은 번호 재사용
TaxiMessage   room → TaxiRoom, member → TaxiMember(null = 시스템), body(200자), kind(text/system), created_at
Report        taxi_room, taxi_message 칸 추가(null 허용). 대상 1개 제약을 4개 중 정확히 1개로 확장, 중복 신고 방지 제약 추가
ModerationLog taxi_room 칸 추가(숨김·복구 기록)
```

- '열림'은 저장값 status=open **그리고** 지금 < departs_at + 1시간. 자동 종료를 기다리는 작업 없이, 조회할 때 시간이 지난 방은
  닫힌 것으로 취급하고, 처음 그 방에 손대는 요청(입장·메시지·목록 조회)이 status=closed, close_reason=expired 로 저장한다.
- 인원 = left_at 이 비어 있는 TaxiMember 수(방장 포함).

## 5. 동작 규칙

| 동작 | 조건 | 결과 |
|---|---|---|
| 방 만들기 | 로그인·이용 제한 아님·열린 방장 방 0개·참여 중 방 2개 미만·출발이 지금~24시간 | 방 + 방장 TaxiMember(number 0) + 시스템 메시지 |
| 입장 | 열린 방·정원 미만·참여 중 방 2개 미만·방장을 차단하지 않음 | 기존 행이면 left_at 비우고 같은 번호, 아니면 다음 번호. 정원이 차면 '정원이 다 찼어요' 시스템 메시지 |
| 나가기 | 참여자(방장 제외) | left_at 기록 + 시스템 메시지 |
| 터뜨리기 | 방장 | status=closed, close_reason=host, 이후 목록·방 화면에서 사라짐 |
| 메시지 | 참여 중·열린 방·도배 제한(10초에 5개) | 저장 |
| 새 메시지 조회 | 참여 중(나간 사람·비참여자는 403) | after=<마지막 id> 이후 메시지 + 인원·상태 |
| 운영자 숨김 | 운영자 | status=hidden, close_reason=moderator, 운영 기록 |

동시성: 입장·방 만들기는 `transaction.atomic` + 방 행 잠금(SQLite 는 쓰기 직렬화)으로 인원을 다시 세어 정원 초과 방지.
동시 입장 테스트(스레드 N개 → 정원만큼만 성공)를 기존 공감 동시성 테스트와 같은 방식으로 둔다.

## 6. 화면 (승인된 시안: list / create / room)

| 주소 | 내용 |
|---|---|
| `/community/taxi/` | 안내 문구, '+ 택시방 만들기'·'이용 규칙', 모집 중인 방(출발 시각 순): 시각·오늘/내일, 출발지 → 도착지, 인원 점(●○), 버튼(참여하기 / 내 방 / 참여 중 / 정원 마감), 안전 안내 |
| `/community/taxi/new/` | 오늘/내일 + 시각, 출발지·도착지(자주 쓰는 곳 칩: 학교(폴리텍대학)·남춘천역·춘천역·시내(명동)), 정원 2/3/4, 한마디(40자), 개인정보 주의 |
| `/community/taxi/<id>/` | 방 정보(경로·한마디·인원·자동 닫힘 시각), 참여자 칩(방장·익명N·나), 대화, 입력창, 나가기/터뜨리기, 신고 |
| `/community/taxi/<id>/messages/?after=` | JSON(새 메시지·인원·상태). 화면이 숨겨지면 멈춤, 방이 닫히면 안내 후 목록으로 |

- JS 없이도: 방 화면은 서버가 그린 대화 + 보내기 폼(POST 후 새로고침)으로 동작. JS 가 있으면 3초 폴링·새로고침 없는 전송.
- 개인 화면이므로 no-store, 서비스 워커 저장 대상에서 제외(기존 커뮤니티와 동일).
- 주소에 계정 ID·아이디 없음. 방 번호만.

## 7. 보관·삭제 (`purge_community` 확장)

- 닫힌(또는 숨김) 지 7일 지난 방 → 방·참여자·메시지 삭제. 처리 전 신고가 걸린 방은 처리 후 7일까지 보관.
- 학생 화면: 닫힌 방은 목록·방 주소 모두 '없는 방'(404와 같은 안내). 운영자만 신고 화면에서 내용 확인.
- 운영 기록(ModerationLog)은 기존처럼 지우지 않되 본문은 남기지 않는다(사유만).
